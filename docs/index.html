PiPOS

A point of sale for small shops and takeaways. Take orders on a tablet, print receipts on a thermal printer. Free and open source.

Everything is set up from the admin panel in the browser: the menu, the layout of the tablet screens, and what the receipt looks like. You drag blocks around, change text sizes and colours, and the tablets pick up the changes within a minute.

tablet  →  your Netlify site  →  Raspberry Pi  →  printer
              ↑
           /admin

You need a free Netlify account, a tablet (any browser), a Raspberry Pi and a USB or network ESC/POS printer (Epson TM-T20, Star, Xprinter and most cheap 58/80mm ones).

Getting started

1. Deploy

Deploy to Netlify. This copies the repo to your GitHub account and builds the site.

2. Set the environment variables

In Netlify go to Site configuration → Environment variables and add:

NameWhat it's for
ADMIN_PASSWORDLogs you into /admin. Also used once on each tablet to connect it.
PRINTER_KEYLets the Pi fetch print jobs. Any long random string, e.g. openssl rand -hex 24.
SESSION_SECRETOptional. Changing it signs everyone out.

Then redeploy (Deploys → Trigger deploy) so the functions see them.

3. Set up your shop

Open https://your-site.netlify.app/admin, log in, and work through Business, Menu and Order types. Hit Save (or ⌘S). It ships with a sample menu so you can try things straight away.

4. Connect the tablet

Open your site on the tablet and enter the admin password once. The tablet stays connected after that. On iPad, use Share → Add to Home Screen so it opens full screen.

5. Set up the printer

See Raspberry Pi. Until the Pi is running, orders wait in the queue and print as soon as it connects.

Admin

BusinessName, second-language name, phone, currency. Turn features on or off: order types, modifiers, second-language names, print queue, daily summary.
MenuCategories and items. Drag to reorder. Items can have choices (pick one before adding, like Chicken / Beef / Prawn) with their own price.
ModifiersAdd or remove options staff can put on an item, like "No onion" or "Extra sauce +£0.50". Each one can apply to every item or only some.
Order typesTakeaway, delivery, or whatever you need. Set what to ask the customer, the ready time, a fee and how many copies to print.
POS layoutDesign the tablet screens. See below.
ReceiptDesign the printed receipt and the daily summary. See below.
OrdersEvery print job, with reprint and retry.
PrinterPaper width, encoding, test print, and the settings to copy onto the Pi.

POS layout

The tablet has two screens, Home and Order. Each one is a grid (12 columns by default) and everything on it is a block: the item grid, the order ticket, category tabs, the print button, text, a clock, an image.

  • Drag a block from the left panel onto the screen.
  • Drag to move it and use the handles to resize. It snaps to the grid.
  • Select a block to change its settings and style on the right: text size, second-language text size, weight, colours, corners, padding.
  • Click empty space to edit the theme: colours, font, base text size, spacing.
  • Pick a device size at the top to see how it looks on your tablet.

Keyboard: arrows move, shift + arrows resize, ⌘D duplicates, delete removes, ⌘Z undoes.

Receipt

A receipt is a list of blocks printed top to bottom. Drag to reorder, click one to edit it, and the preview updates as you go. Click a line in the preview to jump to the block it came from.

Every line has its own size (1× to 8× width and height), bold, underline, white on black, and alignment. The default template prints the order type and ready time big at the top, the customer details, then each item with its second-language name large and the English name and price underneath.

Receipts are laid out in the browser when the order is placed, so changing the template never needs anything updated on the Pi.

Receipt templates

Blocks

TextAny text, with tokens like {customer.name}. Lines where every token is empty are skipped.
ItemsThe order lines. Separate formats and sizes for the second-language line, the main line, modifiers and notes.
TotalsSubtotal, fee, discount and total.
DividerA solid line. Set thickness and spacing.
SpaceBlank lines.
ImageA logo, converted to black and white for the printer.
QR codeAny text or link, with tokens.

The daily summary also has Order types (count and total per type) and Order list blocks.

Any block can be limited to certain order types, e.g. only print the address on delivery orders.

Tokens

{business.name} {business.nameAlt} {business.phone} {business.address}From Business settings
{mode.label} {mode.labelAlt} {mode.short}Order type
{eta}Ready time, e.g. 18:40 or 19:00-19:20
{date} {dateLong} {time}29/10, 29/10/2026, 18:20
{order.number} {order.id}Daily order number, unique id
{customer.name} {customer.phone} {customer.address}What was entered for the order
{items.count} {total}Item count and order total
{summary.date} {summary.count} {summary.total}Daily summary only

Use | for a fallback: {mode.labelAlt|mode.label} prints the second-language name, or the English one if there isn't one.

Raspberry Pi

The Pi sits next to the printer and prints orders as they come in. It waits for a push from ntfy.sh instead of polling, so it only talks to Netlify when there's an order. Any Pi with Wi-Fi works; a Pi 3 A+ or Zero 2 W is plenty.

1. Prepare the SD card

Install Raspberry Pi Imager and pick Raspberry Pi OS Lite (64-bit). In the settings, set a hostname (e.g. pipos), turn on SSH, and enter your Wi-Fi. Write the card, put it in the Pi, plug in the printer and power.

2. Install

ssh pi@pipos.local

curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt-get install -y nodejs git
git clone https://github.com/SnakeLuck360GT/pi-pos.git
cd pi-pos/pi-bridge
npm install

3. Configure

Copy the .env from Admin → Printer into pi-pos/pi-bridge/.env. It looks like this:

API_BASE=https://your-site.netlify.app
PRINTER_KEY=the-same-key-as-netlify
NTFY_TOPIC=pipos-xxxxxxxxxxxxxxxx
PRINTER=/dev/usb/lp0
NameDefault
API_BASEYour Netlify site, no trailing slash
PRINTER_KEYMust match Netlify
NTFY_TOPICShown in Admin → Printer
NTFY_URLhttps://ntfy.shIf you run your own ntfy server
PRINTER/dev/usb/lp0USB printer, or tcp://192.168.1.50:9100 for a network one
ENCODINGfrom admingb2312 if Chinese prints as garbage
CUTpartialpartial, full or none
FALLBACK_POLL_MS300000Safety-net check every 5 minutes. 0 turns it off

4. Test

sudo usermod -a -G lp pi   # then log out and back in
node index.js --test       # prints a test page
node index.js              # waits for orders, Ctrl+C to stop

5. Start on boot

sudo cp pipos-bridge.service /etc/systemd/system/
sudo systemctl enable --now pipos-bridge
journalctl -u pipos-bridge -f    # live logs

The service file assumes the user is pi and the repo is in /home/pi/pi-pos. Edit it if yours differ.

Updating

cd ~/pi-pos && git pull && cd pi-bridge && npm install
sudo systemctl restart pipos-bridge

Troubleshooting

Nothing printsCheck systemctl status pipos-bridge and the logs. Make sure API_BASE, PRINTER_KEY and NTFY_TOPIC match the admin.
No /dev/usb/lp0Check the cable and that the printer is on. Run ls /dev/usb/.
Permission deniedsudo usermod -a -G lp pi and reboot.
Chinese prints as boxesSet encoding to GB2312 in Admin → Printer, or ENCODING=gb2312 on the Pi.
Text wraps oddlySet the right paper width in Admin → Printer (80mm = 48 columns, 58mm = 32).
Tablet says it's not connectedThe admin password or SESSION_SECRET changed. Enter the password again.
Pi keeps rebootingThe power supply is too weak. Use a proper 2.5A one.

Development

git clone https://github.com/SnakeLuck360GT/pi-pos.git
cd pi-pos
npm install
cp .env.example .env   # set ADMIN_PASSWORD and PRINTER_KEY
npx netlify dev        # site + functions on localhost:8888
npm test

React and Vite for the app, Netlify Functions and Blobs for storage, plain Node on the Pi. No database to set up.

Code layout and the data formats are described in docs/SPEC.md. Pull requests welcome.
